# Упрощение UX и точные места обращения к role

17 октября 2026. Backend прочитан, не изменён. Login/Register, auth layout, .env и миграции не редактировались.

## Backend: 15 мест — 8 списков и 7 detail-view

Все находятся в `backend/catalog/views.py`. В таблице — актуальные номера строк условия `self.request.user.is_staff or self.request.user.role == UserRole.ADMIN`.

| Группа view | ListCreateAPIView | DetailAPIView |
| --- | --- | --- |
| Brand | 46 | 58 |
| ProductType | 69 | 81 |
| Product | 94 | Уже использует is_admin(user) |
| ProductImage | 142 | 158 |
| ProductTypeAttribute | 190 | 206 |
| ProductAttributeValue | 222 | 241 |
| ProductVariant | 257 | 268 |
| VariantAttributeValue | 288 | 307 |

Это get_queryset() перечисленных view; их permission IsAdminOrReadonly пропускает SAFE_METHODS без авторизации. У стандартного Django AnonymousUser is_staff=False и нет role. Вычисление `or` поэтому доходит до `user.role`, где возможен AttributeError и 500. SQL-запросу не обязательно успеть выполниться.

В ProductDetailAPIView владелец уже применил `is_admin(self.request.user)`; общий helper в accounts/permissions.py сначала проверяет is_authenticated через `and`, поэтому для гостя обращение к role не выполняется. Этот view не включён в 15 мест. В CategoryListCreateAPIView владелец уже заменил permission создания на IsAdminOnly; прежнее предупреждение о требовании staff для создания категории более не актуально. StockAdjustAPIView всё ещё использует IsAdminUser.

Это повторная проверка текущего исходного кода, а не воспроизведение живого HTTP 500. Исправления backend оставлены его владельцу.

## Изменения UX

- Главная: понятный заголовок, один основной переход в коллекцию, быстрые ссылки на типы товаров из API/mock. Убраны лишние подписи, декоративный ряд обещаний, длинные блоки с категориями/философией; вместо них короткая помощь с выбором. Исходные фотографии и маршруты категорий сохранены.
- Навигация: коллекция, категории, контакты; на широком экране поиск из шапки, без его дублирования на странице каталога/поиска. Мобильные меню, нижняя навигация, обе темы и проверяемый вход ADMIN сохранены.
- Коллекция: компактнее заголовок и отступы; поиск доступен не только в /search. Длинные характеристики свёрнуты по умолчанию без выбранного типа, но раскрываются для выбранного типа/активной характеристики.
- Выбранные фильтры показаны читаемыми кнопками: можно убрать один, не сбрасывая остальные. URL-состояние, reload, сортировка, динамическая схема атрибутов и мобильный drawer сохранены.
- Карточки: крупное фото, название и цена; повторяющаяся кнопка «Подробнее» заменена компактной стрелкой с доступным названием. На 320–429 px одна колонка, чтобы не сжимать товар и цену. От 430 px сохраняется многоколоночная сетка.
- ADMIN по-прежнему видит «Изменить», но действие визуально тише. Проверка роли, API permission probe, guards и защита от смешения demo/API ID не обходятся.
- Товар: цена, наличие, варианты и контакт идут перед длинным описанием; описание раскрывается отдельно. Галерея, реальные варианты, характеристики, избранное и мобильное контактное действие сохранены.
- Вечерние цветные поверхности и cyan-акцент сохранены. minimalist-ui использован для иерархии, простых плоских поверхностей и сокращения декоративного шума. Auth и layout админки не переделывались.

Дополнительно: общий `src/lib/auth/session-query.ts`, его использование в `components/admin/admin-entry.tsx` и `components/store/account-shell.tsx`. Это исправляет гонку при позднем монтировании потребителей общей сессии: после 503 не делается неявный повтор, способный подменить ошибку сообщением «войдите». При уходе на авторизацию неиспользуемый cache удаляется; после входа читается новая сессия. Login/Register и JWT-прокси не изменены. Отдельный тест проверяет Next Link → login → account без перезагрузки, после 401 и после 503/retry/401.
