## Запуск

```sh
npm ci
npm run dev
```

По умолчанию каталог использует **Django API**; backend должен быть доступен по `DJANGO_API_ORIGIN` (по умолчанию `http://127.0.0.1:8000`). Demo доступен только по явной настройке `SIFAT_CATALOG_SOURCE=demo`, не записывает favorites и не заменяет ошибки API. Существующие фотографии и fixtures сохранены.

После наполнения каталога через ваш Swagger/Admin:

```sh
SIFAT_CATALOG_SOURCE=api DJANGO_API_ORIGIN=http://127.0.0.1:8000 npm run dev
```

Для production:

```sh
npm run build
SIFAT_CATALOG_SOURCE=api DJANGO_API_ORIGIN=http://127.0.0.1:8000 npm run start
```

Источник выбирается при старте сервера. Storefront использует динамический рендеринг; для сборки Django не нужен. В API-режиме ошибка или пустой список **не заменяются демотоварами**. Серверный cache GET — до 60 секунд.

## Данные и контракты

- `src/lib/commerce/catalog-contracts.ts` — типизированные read-проекции существующих сериализаторов Django. Поля и числовые FK соответствуют API, decimal остаются строками до преобразования. Неиспользуемые timestamps и вложенные display-only объекты не моделируются.
- `mock/catalog.ts` — набор ответов: категории, типы, товары, изображения, определения/привязки/значения атрибутов, варианты и значения вариантов. Не view-model fixtures внутри React.
- `catalog-mapper.ts` — **общий mapper для mock и API**. Преобразует цены, связывает FK, исключает неактивные записи. Без вариантов остаток неизвестен, не выдумывается.
- `catalog-api.ts` — GET одной страницы `products/`, справочников и изображений; detail через `product/{id}/` с вложенными данными. Без обхода всех product pages и коллекций атрибутов/вариантов. Подробности — в PAGINATION.md.
- `catalog-attributes.ts` использует `can_be_variant_option`, `is_filterable`, `sort_order`, тип и единицы. `false` → «Нет», `0` не теряется.
- `variants.ts` — селекторы по структурированным значениям, без разбора названия SKU. Смена ведущей характеристики сбрасывает несовместимые последующие; если остаётся единственный вариант значения, он выбирается автоматически. Невозможные комбинации недоступны, нулевой остаток явно отмечен.
- `browse.ts` — локальная фильтрация только явного Demo. В API-режиме поддерживаемые параметры отправляются Django до пагинации; отсутствующие серверные фильтры не имитируются локальным отбором текущей страницы.
- `favorites-api.ts` / `favorites-provider.tsx` — серверное избранное, user-scoped cache, авторизация, состояния ошибок/загрузки. localStorage не источник избранного; Demo не сохраняет товары.

Демо: категории «Мебель» и «Электроника», отдельные ProductType. Четыре предмета мебели и Apple MacBook Air M4: 16/256 (4 шт.), 16/512 (7 шт., скидка), 24/512 (0 шт.). Все цены, характеристики и остатки иллюстративные.

Они доступны на `/contact` и в окне связи из карточки товара. Backend и .env для этого не нужны.

Необязательные публичные настройки для другого deployment:

- `NEXT_PUBLIC_STORE_PHONE` — реальный номер магазина в международном формате.
- `NEXT_PUBLIC_STORE_MESSAGE_URL` — согласованная HTTPS-ссылка на мессенджер/канал связи.

Передайте их через окружение **до сборки** (NEXT_PUBLIC встраивается в клиентскую сборку); .env агент не меняет. `NEXT_PUBLIC_STORE_PHONE` переопределяет указанный номер, пустое/невалидное значение отключает звонок. `NEXT_PUBLIC_STORE_MESSAGE_URL` добавляет ещё один канал связи; Telegram доступен независимо от него.

ContactCTA открывает sheet/dialog с названием, вариантом, SKU, типизированными характеристиками и ценой. Можно скопировать текст; при запрете Clipboard API — выделить вручную. Телефонный звонок не отправляет эти данные автоматически: клиент сообщает их менеджеру.
