## Что было недоработано

CRUD-формы уже существовали, но вход в управление был спрятан в профиле, а фото, варианты и характеристики открывались отдельными списками без контекста товара. После создания не было перехода к следующим шагам. Это UX-недоработки frontend, а не отсутствие всех CRUD-функций.

## Новый сценарий

1. Администратор открывает панель из шапки витрины, мобильного меню или профиля. USER/MANAGER не видят ссылки и не проходят guard.
2. На `/admin` нажимает «Добавить товар»; в списке товаров — «Создать товар».
3. `/admin/products/new` показывает форму и ссылки на недостающие категории, типы и бренды. По умолчанию создаётся DRAFT. Другие разделы закрыты до успешного сохранения.
4. После сохранения открывается `/admin/products/[id]` — единая карточка: основная информация, фотографии, варианты, характеристики товара, опции вариантов.
5. Списки/выбор товара/вариантов внутри карточки ограничены её товаром. Формы переиспользуют существующие типизированные модели, валидаторы, реальный API либо isolated demo adapter. Характеристики определяются схемой ProductType, не фиксированными Color/Width.
6. Для публикации выбирает ACTIVE и «Активно» в основной форме. Остатки по-прежнему проводятся отдельной подтверждаемой складской операцией.

Demo не публикует товар на витрину и не пишет в Django; режим обозначен постоянной плашкой. API-ошибки не превращаются в demo-успех. Источник выбирается серверной конфигурацией, не кнопкой клиента.

## Замечания backend — только чтение, без исправлений

- `catalog/views.py`, CategoryListCreateAPIView и StockAdjustAPIView: создание категории и корректировка склада используют IsAdminUser, поэтому требуют is_staff, хотя общий permission допускает роль ADMIN. Возможен 403 для ADMIN без staff.
- В нескольких публичных queryset, начиная с BrandListCreateAPIView, есть `self.request.user.role` без проверки is_authenticated. Django AnonymousUser не имеет role: это потенциальный AttributeError/500 для гостевого запроса. Вывод по коду, не результат выполнения живого GET в этой проверке.
- API заказов и избранного не создавались. Backend, БД, миграции, .env и Login/Register не изменялись.
