## Контракт

| GET, относительно `/api/v1/catalog/` | Использование во frontend |
| --- | --- |
| `attributes/` | Название, `data_type` (`TEXT`/`NUMBER`/`BOOLEAN`), единица измерения |
| `product-type-attributes/` | Связь с ProductType, порядок `sort_order`, доступность фильтра `is_filterable` |
| `product-attribute-values/` | Значения по `product` и `attribute`: `value_text`, `value_number`, `value_boolean` |

Из значений и привязок формируются характеристики карточки и фильтры каталога. Поля не привязаны к названиям «Цвет/Ширина» и не зависят от конкретного типа мебели. Значения `0`/`false` сохраняются; boolean отображается как «Да/Нет», число — с локализованной записью и единицей. Фильтрация выполняется на frontend; несуществующие параметры фильтрации Django не отправляются.

## Первые ответы при проверке 20 сентября 2026

Только GET к локальному Django `http://127.0.0.1:8000`. Источник причины — поле **Exception Value** в HTML-ответе Django, не предположение по одному только статусу 500. Ошибки ниже — снимок на момент проверки, после исправлений их нужно перепроверить.

| Endpoint | Статус | Ответ |
| --- | --- | --- |
| `products/` | 200 | Пустой список |
| `categories/` | 200 | 2 категории |
| `product-types/` | 200 | Пустой список |
| `product-image` | 500 | `relation "catalog_productimage" does not exist` |
| `attributes/` | 500 | `relation "catalog_attribute" does not exist` |
| `product-type-attributes/` | 500 | `relation "catalog_producttypeattribute" does not exist` |
| `product-attribute-values/` | 500 | `Cannot resolve keyword 'sort_order' into field` |

`relation ... does not exist` означает, что ORM-запрос обращается к отсутствующей таблице в подключённой PostgreSQL-базе. Сам ответ не отличает неприменённые/отсутствующие миграции от подключения к другой базе. Backend-разработчик подтвердил, что миграции ещё не выполнял.

Для `product-attribute-values/` причина была другая: в `ProductAttributeValueListCreateAPIView.get_queryset()` использовалась `.order_by('sort_order', 'id')`, а у `ProductAttributeValue` нет поля `sort_order`. Применение миграций для других таблиц само по себе не исправляет такую сортировку. При первом read-only просмотре также были обнаружены два объявления `class ProductAttributeValue` в `backend/catalog/models.py`.

## Почему `/auth/me/` мог писать `401` красным

`401 Unauthorized` — нормальный ответ проверки текущего пользователя, если JWT-cookie отсутствует или больше недействительна. Django `runserver` окрашивает HTTP 4xx в красный как предупреждение, но это не означает падение сервера.

Frontend-прокси теперь проверяет отсутствие обеих httpOnly-cookie (`sifat_access` и `sifat_refresh`) перед запросом `GET /auth/me`: для обычного гостя он сам возвращает ожидаемый 401 и не обращается к Django. Это подтверждено запуском frontend с намеренно недоступным `DJANGO_API_ORIGIN`: `/api/backend/v1/auth/me` всё равно корректно вернул 401, а не 503. Если cookie существует, но токен истёк/повреждён, запрос до Django и один 401 возможны; затем существующая логика пытается обновить access-токен через refresh.
