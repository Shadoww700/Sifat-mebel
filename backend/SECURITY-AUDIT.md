# Sifat-Mebel: ограниченный аудит backend/frontend, 21 октября 2026

Область: четыре пункта приложенного задания — изображения, административные permissions, приватность Favorites, публичная видимость. Это не заключение о полной готовности production и не нагрузочный тест. Модели, миграции, рабочая БД, настройки PostgreSQL, .env, секреты, дизайн и Login/Register не изменялись.

## Подтверждено и исправлено

- Каталог читал одну страницу товаров, но общий справочник изображений. Теперь существующий slashless `GET /api/v1/catalog/product-image` принимает `product_ids=1,2` (1–100 положительных bigint ID, повторения удаляются) и/или `product_id=1`. Два фильтра пересекаются; несуществующие ID дают пустой массив. Неверный или явно пустой фильтр даёт 400, без fallback к полному списку. Фильтр действует поверх прав доступа. Прежний нефильтрованный административный список и POST/PATCH multipart сохранены.
- Frontend передаёт только ID полученной страницы, один запрос изображений без кеширования. Каталог остаётся на серверной пагинации; detail не читает весь каталог. Число JSON-запросов прежнее, уменьшается объём ответа изображений. Backend необходимо развернуть перед новым frontend: старый endpoint проигнорирует неизвестный фильтр.
- Общий `catalog/visibility.py` проверяет Product.active, ACTIVE/OUT_OF_STOCK, активность Brand, ProductType и Category. Проверка применяется к продуктам, изображениям, значениям атрибутов и вариантам; у вариантов дополнительно требуется is_active. ProductType и его схема требуют активной категории. Для привилегированных пользователей скрытые записи доступны, включая отключённые категории; для остальных параметры запроса не ослабляют границу.
- Favorite detail/delete теперь всегда ограничен владельцем, включая ADMIN/staff. Чужой и отсутствующий ID дают одинаковый 404. List/create уже были персональными: поведение сохранено. Повторный POST остаётся 200 после первого 201, уникальность `(user, product)` не менялась. Ответ содержит только id/product/created_at; скрытые подробности не вкладываются, сохранённое избранное можно удалить после архивации товара.
- StockAdjust использует IsAdminOnly, как продукты и журнал. Это существующая backend-политика `authenticated AND (role=ADMIN OR is_staff)`, а не новая роль. USER/MANAGER без staff-флага запрещены. Дополнительно некорректный variant_id журнала даёт 400 вместо ValueError/500.
- Убраны N+1 чтения Attribute в вложенных значениях Product detail: prefetch с select_related('attribute'). Запрос изображений select_related('product') не выполняет SQL на каждую карточку.

## Решение владельца по доступу к интерфейсу

Frontend по предыдущему явному требованию допускает в управление только роль ADMIN и проверяет backend permission через OPTIONS. Backend исторически допускает также is_staff=True. Этот флаг frontend не получает от /auth/me и не угадывает. Уточнение отправлено владельцу: оставить ADMIN-or-staff в backend или перейти на role-only во всём API. Пока сохранён смысл общей backend-политики и более узкий frontend-доступ; UI не является защитой API. MANAGER без staff нигде не включён как административная роль.

## Ограничения

Изменение queryset защищает JSON API, но не закрывает прямой доступ к ранее известному URL файла из публичного media-хранилища. Для приватных файлов нужна отдельная политика хранения/выдачи; автоматически её не вводили.

Динамические фильтры характеристик, stock-фасеты, точный фильтр ProductType и стабильный вторичный порядок страниц остаются отдельными предложениями из frontend/PAGINATION.md, а не реализованными контрактами данного этапа. Глобальные справочники управления по-прежнему не пагинированы. Общий нефильтрованный endpoint изображений сохранён для обратной совместимости; витрина его больше не вызывает.
